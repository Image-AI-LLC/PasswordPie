# Search ranking

Search matches every word of the query, then orders the matches. The order is:

1. **Favorites first.** The user's own pick outranks everything.
2. **Score**, high to low: `score = match × (1 + boost)`.
3. **Title** A to Z, then entry ID, so the order is stable.

Prefix hits are one pass and substring-only hits are a second pass. The second pass runs only when the first finds nothing.

## match (0 to 1, per word, then averaged over the query's words)

| Hit | Score |
|---|---|
| a whole word of the title or host | 1.0 |
| start of the first word | 0.8 |
| start of a later word | 0.6 |
| inside a word (second pass only) | 0.4 |
| only in username, notes, tags or custom fields | 0.2 |

A word with punctuation (`github.com`) matches the title or host as a whole at 0.8.

## boost = 0.24 × (0.6 × recency + 0.4 × site)

| Signal | What it is | Range |
|---|---|---|
| **recency** | When the user last used the account. `0.5 ^ (days since / 30)`: 1 today, 0.5 after 30 days, 0.125 after 90 days. Unknown or never used is 0. | 0 to 1 |
| **site** | Popularity of the site's root domain from the bundled top 10,000: `1 − ln(rank) / ln(10001)`. A subdomain uses its parent's rank, unless the subdomain has its own entry in the table (then it keeps its own). Unranked is 0. | 0 to 1 |

- Recency counts 60% and site rank 40%. Recency is the user's own behavior. Site rank is only a general prior.
- The boost is at most 0.24, under 0.25. The closest match classes differ by a factor of 1.25 (1.0 against 0.8), so the boost
  reorders accounts inside a match class and never lifts a weaker class over a stronger one.

Examples (same match score):

| Account | recency | site | boost |
|---|---|---|---|
| top-ranked site, never used | 0 | 1.0 | 0.096 |
| internal tool (unranked), used 7 days ago | 0.85 | 0 | 0.122 |
| github.com (rank 50), used 60 days ago | 0.25 | 0.58 | 0.092 |
| internal tool (unranked), used yesterday | 0.98 | 0 | 0.141 |

## Where "last used" comes from

KeePass has no usable value (`LastAccessTime` equals the creation time), so PasswordPie keeps its own record:

- **In PasswordPie:** copying a username, password or one-time code, filling, and opening the website. Looking at an entry does not count.
  Stored in `usage.json` in the app's Application Support folder (mode 0600), as entry ID and time only. It is not inside the KeePass file.
- **Live Chrome logins (direct channel):** Chrome's own `date_last_used`. If both exist, the later one is used.
- Saving a live Chrome login to KeePass keeps its last-used time.
- One account on several sites is one row, and it ranks by the latest use of any of its sites.
